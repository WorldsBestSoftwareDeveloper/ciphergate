# CipherGate Project Context

Last updated: 2026-05-11

## What This Project Is

CipherGate is a Next.js + Solana/Anchor + Arcium prototype for encrypted file access control.

The intended product flow is:

1. Browser encrypts a file client-side with AES-GCM.
2. Encrypted file ciphertext is stored outside the chain, ideally IPFS.
3. Solana stores asset listings, prices, policies, payments, and access records.
4. Arcium stores or controls the encryption key and releases it only when access policy checks pass.

## Current Demo Limitations

The app is currently a demo/prototype, not a fully decentralized production app.

- Asset listings are stored in browser `localStorage`.
- Access records are simulated in browser storage.
- IPFS is simulated with browser-local IndexedDB/session storage unless a real storage token/provider is configured.
- Arcium MPC is simulated in `lib/arcium.ts`; real Arcium functions still throw errors.
- Devnet wallet connection and airdrop can work.
- Devnet SOL transfers may work depending on purchase flow, but the marketplace registry is not fully on-chain yet.
- Two-wallet testing works best inside the same browser profile by switching Phantom accounts.
- Different browsers/profiles/devices may not see listings or decrypt files because demo state is browser-local.

## Devnet Clarification

Solana devnet can support real on-chain storage for:

- asset listing metadata
- creator address
- price
- expiry/max-use policy values
- IPFS CID
- Arcium policy/key reference
- access records
- revoke flags/timestamps

Solana should not store:

- raw files
- AES keys
- private secrets

Arcium is a separate MPC/key-control layer. It is not replaced by pure Solana devnet. Mainnet is not required for early real Arcium work; the intended path is Solana devnet plus Arcium devnet/testnet/dev tooling if available.
